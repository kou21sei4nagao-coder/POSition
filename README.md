# POSition（レジ番メーカー・オフライン版）

その日のシフトを貼り付けると、9:00〜21:00のレジ番を1時間ごとに自動で割り当てるiPad向けアプリです。

## 使い方
1. 「名簿」タブ：シフト表のC列（名前）を一番上から一番下まで、部門の間の空白も含めてコピーして登録（最初の1回と、人が増減した時だけ）
2. 空白で区切られたグループごとに部門を選び、役職・レベルを設定
3. 「今日のシフト」タブ：作りたい日の列を、名簿と同じ行から同じ行までコピーして貼り付け
4. 照合結果で名前と時間がずれていないか確認し、「レジ番表を作る」

## データの扱い
- 名前・シフト・スタッフ設定は、使っているiPadの中（ブラウザの保存領域）だけに保存されます
- 外部へデータを送る処理は入っていません（ページ内の設定で、外部サイトへの通信も禁止しています）
- GitHubに置くのはアプリ本体だけです。実名の入ったファイルはリポジトリに入れないでください

## 公開手順（GitHub Pages）
1. GitHubで新しいリポジトリを作る（例：`regiban`、Public）
2. このフォルダの中身をすべてアップロードする
3. リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save
4. 数分後に `https://ユーザー名.github.io/regiban/` で開けるようになる

## iPadへのインストール
1. 上のURLをSafariで開く
2. 共有ボタン → 「ホーム画面に追加」
3. 一度開いたあとは、機内モードでも動きます

## バックアップ
- スタッフ画面の「書き出し」で設定をファイルに保存
- 機種変更や別のiPadでは「読み込み」でそのファイルを選ぶと復元

## 割り当てルール
- レジに入るのはPN・新入社員・No2・PNリーダー（リーダー・店長は入らない）
- 部門で「店長」「流通便」を選んだ人は、レジにもフロアの人数にも入らない
- 決める順番：手動で固定した時間 → 締め（20:00〜21:00） → 入れる人が少ない時間帯から
- 優先順位（上ほど強い）
  1. 締めは「締め」にチェックした人（レベル1 → 2 → 3 → 4）。締めの人がいない日は、ほかの時間と同じ決め方にして警告
  2. 部門のフロアを0人にしない
  3. レベル4は最後
  4. 今日の回数が少ない人から
  5. 同じ人の2時間連続を避ける（3時間連続は固定の前後も含めて禁止）
  6. 売り場のカバー：季節AV・家電・情報は3部門で1つのフロア（3人以上残す）、通信は別（1人以上残す）。足りなくなるときは余裕のあるフロアから出す
  7. 役職 PN → 新入社員 → No2 → PNリーダー、同じ役職の中でレベル1 → 2 → 3
  8. まだ入っていない人が多い部門から → 部門のレジ回数を均等に → 人の多い部門 → 日替わり
  - 見習い（レベル0）は自動では入れない（手動でのみ）
- プラン：標準／部門重視（人の少ない部門を売り場に残し、多い部門から出す）／別パターン（同じルールで夕方から埋める）。手動固定は全プラン共通
- 「テキストでコピー」を押した日に、使ったプランと手で直した枠の数をiPad内に記録（名前は記録しない）。ルール表の下に集計を表示
- 時間帯をタップして担当を変更できる（休憩は上長が現場で調整）
- レジ番表の右に、その日の出勤者と時間・レジに入った時間・回数を並べて表示（名前をタップすると、その人のレジの枠が強調される）

## 更新するとき
- アプリ名の横の「v36」などがバージョン。sw.js の `position-v36` と必ず同じ番号にする
- 更新前に、旧版から新版への更新・名簿の保持・割り当て・手動変更・コピー・書き出し/読み込み・機内モード・外部通信なしを自動テストで確認する
- 確認が済んだら index.html と sw.js を上書きアップロード。ネットにつながっている時は、アプリを開くたびに最新版を読み込む
- 反映後、iPadでアプリを開き直し、バージョン表示が新しい番号になったことを確認する
- 不具合が出たら、ひとつ前の版のファイルを上書きアップロードすれば元に戻る（名簿は消えない）
